## Honest reading

1. **A ceiling effect ate the headroom.** The baseline passed 8/10 — Sonnet handled MeterHub's "harder" feature well without diagrams — so B's maximum possible gain was +2, and it scored +1 (9/10). A threshold designed for a 6/10 baseline is nearly unreachable against an 8/10 one. This is an instrument problem as much as an effect-size problem: detecting a diagram effect needs a fixture where the baseline fails ~half the time.
2. **The bait never produced an invented integration.** At this model tier, on clean sub-100-file fixtures with a frozen spec, inventing nonexistent services or endpoints appears to be a non-failure-mode, and the proposal's "fewer hallucinated integrations" claim should leave the headline argument until someone demonstrates that failure mode occurring at all. _Correction 2026-10-16: a grader defect originally reported all arms as 0.0; the corrected re-grade shows arm B at 2.3 unresolvable references per run — on inspection all unrealized planned paths or src-omitted spellings, not invented integrations — see `2026-10-16-c4-eval-grader-correction.md`. The verdict is unaffected (the rule keys on arm A's mean, which remains 0.0)._
3. **Direction stayed consistent, cost stayed nil.** B outperformed A in both campaigns (+2 and +1 passes), never underperformed, showed less drift both times (9.8 vs 10.6 here; 5.3 vs 6.7 in phase 1), and cost nothing on this fixture (identical mean tokens, B actually faster by ~8% wall-clock). Diagrams never hurt anything in 50 runs.
4. **Combined, pre-registration-honest state:** one campaign positive at exactly the threshold, one below it. Per the phase-2 pre-registration, this is "one positive, one null at threshold → iterate on the diagram convention rather than shipping or abandoning". The pooled view (B 17/20 vs A 14/20 passes across both fixtures) is suggestive but was not a pre-registered endpoint and must not be quoted as one.

## What this means for the proposal

The hard-data claim the skeptics asked for now reads:

> Across two independent fixtures and 50 runs: C4 diagrams never degraded any measured dimension, cost between 0% and 3.5% extra tokens, improved the implementation pass rate in both campaigns (+2/10 and +1/10), and met the pre-registered success bar in one of two campaigns.

That supports **"promising, cheap, and safe — not yet proven"**. Defensible paths from here, for the human decision:

- **(a) Adopt as optional** (recommended): ship the diagram sections as an _optional_ convention in the templates (the proposal's own fallback position), citing both campaigns. The measured cost is ~nil and the measured direction is consistently positive; what is unproven is only that the effect is large.
- **(b) One more campaign with a calibrated fixture**: build a third fixture tuned so the baseline passes ~5/10 (more containers, a subtler cross-container feature), giving the threshold real headroom. Only worth it if a _required_ template change is the goal.
- **(c) Stop here** and keep prose-only templates. Hard to justify given 50 runs with zero measured downside.

The Week-3 decision step from the proposal should pick among these; this note recommends (a), with (b) available if reviewers want "required" instead of "optional".
