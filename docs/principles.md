# Principles

A one-page reference to the eleven principles `awos` is built on. Each entry gives the principle and its opening statement. The full reasoning behind each one is in [Philosophy](philosophy.md).

## 1. Judge by outcome

The measure of `awos` is whether what ships is what was wanted, the first time.

## 2. Intent is gathered, then confirmed

The human is the authority on intent, but not necessarily its only source.

## 3. Understanding is confirmed before anything is built

There is always a moment where the human can see what the agent understood and say "yes, that" or "no, not that."

## 4. The agreement is the contract for the build

Implementation is judged by how faithfully it realizes the confirmed understanding.

## 5. `awos` checks its own work

`awos` does not consider work done until it has made sure of it itself.

## 6. Write for the reader

Agents and humans need information presented differently.

## 7. Make the missing parts reviewable

What is written in a specification is easy to review. What is missing is much harder to notice, even when it is essential.

## 8. The project remembers

Knowledge produced by a change outlives the change.

## 9. `awos` owns one path

Intent → confirmed understanding → implementation → verification.

## 10. `awos` speaks one host, natively

`awos` is built for Claude Code, by design.

## 11. `awos` is for work worth specifying

Reaching agreement before building takes time.
