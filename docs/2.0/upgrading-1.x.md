# Upgrading to the 1.x preparation release

This guide covers the 1.x release that prepares AWOS 2.0 (Phase 0 in [`roadmap-2.0.md`](roadmap-2.0.md)). AWOS 2.0 itself is the later release in which the `better` commands become core; releases that change the command set before then add their own section here.

This release narrows the framework to its core method: agree on what to build, then build it. Two commands and the brownfield onboarding leave the framework — but nothing of yours is deleted: the retired roadmap command is shut down gracefully (its local body becomes a removal notice and its template is removed; your documents stay untouched), and commands the flow plugin generated for you keep working. Updating is the same command as always:

```sh
npx @provectusinc/awos
```

Migrations handle the rest.

## What left the framework, and what replaces it

| Removed               | Replacement                                                                                                                                                                                                                                                                                                                                                                                                                         |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/awos:roadmap`       | Specs are anchored by an explicit topic: run `/awos:spec` and state what you want to build. Running `/awos:roadmap` now answers that the feature left AWOS; the update tells you so once, naming the two files to delete if you want the command gone. Your `context/product/roadmap.md` is untouched — keeping it current is yours to do — and while it exists, the spec topic question offers its incomplete items as candidates. |
| `/awos:flow` (plugin) | Nothing — commands it already generated for you keep working when given a feature or bug to work on. Their empty-argument path resumed from the next unchecked roadmap item, which nothing ticks any more, so pass the feature explicitly. Their fixed prose still says "change this command by re-running `/awos:flow`" — that command is gone, so edit the generated files directly.                                              |
| Brownfield onboarding | Partly automatic: `/awos:architecture` inspects the codebase and adopts your existing technology stack as evidence-cited defaults you confirm in review. Product-level intent (what the product does, for whom) is not read from code — it comes from the `/awos:product` interview.                                                                                                                                                |

"Keeps working" applies to the commands `/awos:flow` generated for you — they are yours, and AWOS never touches them. The retired `/awos:roadmap` is shut down gracefully instead: nothing of yours is deleted, but the local copy of the command body is replaced with a removal notice, so calling it tells you (and the agent) that the feature left AWOS rather than running a frozen 1.x copy. One thing to know: the spec flow no longer _builds on_ the roadmap (the topic is the anchor), so a roadmap you keep maintaining feeds specs only through the topic-candidate offer above.

## What the update does to your project

| File                                                 | What happens                                                                                                                                                                                                                                                           |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `.awos/commands/roadmap.md`                          | Replaced with a removal notice where present, and created where only your wrapper remains — so `/awos:roadmap` answers that the feature left AWOS instead of running the 1.x copy.                                                                                     |
| `.awos/templates/roadmap-template.md`                | Deleted — nothing reads it once the command is a notice; the roadmap you keep is `context/product/roadmap.md`, which stays yours.                                                                                                                                      |
| `.claude/commands/awos/roadmap.md`                   | If you customized it: preserved byte-for-byte, and it now resolves to the removal notice. If it is still the wrapper 1.x shipped: rewritten to a wrapper whose description says the command was removed — it resolves to the same notice, so calling it still answers. |
| `context/product/roadmap.md`                         | Preserved: AWOS no longer creates or updates it, but `/awos:spec` offers its items as topic candidates while it exists. Note that `/awos:verify` no longer marks items complete — if you keep using the roadmap, tick shipped items yourself. Yours to keep or delete. |
| `/implement-feature`, `/fix-bug`, `delivery-flow.md` | Preserved and disowned — generated for you, they keep working when given an argument, they're yours now.                                                                                                                                                               |
| `context/product/brownfield.md`                      | Preserved, but no longer read: 1.x wrote it during onboarding for `/awos:architecture` to absorb and delete, and nothing reads it now — `/awos:architecture` re-inspects the codebase on every run instead. Yours to keep or delete.                                   |

## The research-first spec command

A later 1.x minor makes `/awos:spec` research-first. The command set does not change and neither does the deliverable: `context/spec/NNN-name/functional-spec.md` is written from the same template to the same place, and `/awos:tech` and everything downstream read it unchanged. What changes is how the spec is reached, and what else the directory holds afterwards.

| What you see                                      | What it is                                                                                                                                                                                                                                                                                                                                                                                               |
| ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A question about knowledge sources at the start   | When `context/sources/sources.md` is absent, the command offers once to discover the project's sources (via the `configure-external-sources` skill from the awos plugin, when installed) or skip for this spec. Suggested, never enforced.                                                                                                                                                               |
| Research runs before you are asked anything       | Codebase and web research agents run in parallel as soon as the topic is known; an internal-KB agent joins when `sources.md` is configured with a non-manual source.                                                                                                                                                                                                                                     |
| `feature-brief.md` next to the spec               | What the feature is today, in plain language: vocabulary, current flow, dependencies, effects, quirks, open questions. The command points you at it and holds an open conversation until you explicitly confirm it; a brief left `Draft` resumes later with `/awos:spec <spec-number>`.                                                                                                                  |
| `research-notes.md` next to the spec              | The raw technical findings behind the brief. Nothing reads it automatically; the tech phase can draw on it.                                                                                                                                                                                                                                                                                              |
| A second agent reads the finished spec            | The blind `spec-verifier` is dispatched with only the spec path and reports what a reader with no project context cannot understand. The installer puts it at `.claude/agents/awos/spec-verifier.md` — a new subfolder inside your agents directory; the root of `.claude/agents/` stays yours and is never written by the installer. Like the command wrappers, it is preserved on update once present. |
| `functional-spec.html` next to the spec           | A human-facing review page rendered by `.awos/scripts/render-spec.mjs` (needs `node` on PATH; skipped, never fatal, without it). A point-in-time snapshot — the markdown stays canonical. After rendering, the command offers to publish the page as a private Claude artifact; an unanswered question means no.                                                                                         |
| `/awos:spec 014` amends, `/awos:spec 014` resumes | Both go by what the spec directory holds: a `functional-spec.md` routes to the in-place amendment (Update Mode, unchanged), a `Draft` brief without a spec resumes the understanding gate.                                                                                                                                                                                                               |

Unattended runs (`AWOS_UNATTENDED=1` with a topic) skip the sources offer, the topic question and the gate, never publish, and still write every file, marking the spec as drafted from research alone.
